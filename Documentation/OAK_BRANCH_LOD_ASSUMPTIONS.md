# Oak Branch LOD assumptions and simplifications

These choices define the initial experiment in the [clustered triangle LOD plan](OAK_BRANCH_CLUSTER_LOD_PLAN.md). The baker and selector should work on general triangle meshes. Oak Branch supplies the first visual test.

| Area | Initial choice | Revisit when |
|---|---|---|
| Input and authoring | Use the existing GLB. Derive component membership from shared indexed triangle edges for this foliage primitive. The export check found 3,080 components of 40 triangles each by both indexed and exact-position edge matching. Blender authors source geometry. The offline engine-side baker builds the LOD data. | Another mesh has ambiguous connectivity at attribute splits, or spatial grouping proves poor. Consider exporting topology IDs or flat group labels in those cases. Bark already gives different component counts under the two edge-matching methods. |
| Fixed groups | Pack nearby whole components into fixed groups. Keep every component and bake full detail plus two coarser levels. Keep bark at full detail for the foliage comparison. Track source component survival across complete representations. | The first results show that useful reduction requires changing component distribution, or that the fixed groups have poor locality. Evaluate whole-component removal separately with coverage and gap measurements. |
| Open outlines | Lock open borders and simplify interiors first. For a leaf, the tip and rim stay in place while interior curvature can change. Accept the reduction the locks permit and report when they prevent reaching a target. | Interior simplification offers too little reduction. Compare a second recipe that permits controlled rim changes and check silhouette, gaps, and shadows. |
| Shared boundaries and attributes | Keep identical edge positions and segmentation wherever groups can switch independently across a shared edge. Verified geometric adjacency can cross a UV or normal split while the draw vertices retain separate attributes. Whole-component foliage groups have no shared mesh edges. | Connected geometry crosses group boundaries and locked seams impede reduction. Test whether regrouping makes those edges interior while preserving valid mixed-detail cuts. |
| Bake and error | Use an offline C++ baker in the engine repository. Use meshoptimizer for edge-collapse simplification and log its simplifier error. For fixed groups, bake two-way sampled point-to-triangle deviation against the original component in object units. Project it per camera at runtime. Treat the sampled value as an estimate and record coverage separately. | Forced cuts that look good consistently disagree with automatic selection. Compare the positional estimate to silhouette, gap, and shadow differences on the same views. |
| Partitioning | Start with meshoptimizer's capped builder and a configurable cap, with 128 triangles as an initial test value. | Packing or seam density becomes limiting. Compare METIS with the same input topology and caps before considering a custom solver. |
| Viewer | Keep the indexed draw path and every representation resident. Use the same chosen representation for the camera and shadow passes. Inspect forced levels with stable unlit triangle and group tints, then use freeze cut to examine an automatic selection while moving the camera. | A valid and visually useful cut is established. Evaluate cluster culling separately under [Future considerations](FUTURE_CONSIDERATIONS.md#rendering). |

The rim-collapse follow-up adds a fourth baked level alongside the locked-rim levels. Oak Branch supplies a UV convention for identifying the tip and attachment anchors. The same baker can use the farthest rim pair on meshes without that convention. Rim deviation is sampled in both directions and limited relative to the anchor span. Components that fail the check retain their previous geometry. See the [follow-up results](OAK_BRANCH_CLUSTER_LOD_PLAN.md#rim-collapse-follow-up).

The area-fit follow-up adds two forced levels with new vertices. The fit assumes open, consistently wound strips with the attachment and tip on the UV0 centerline and width across U. Enable it for assets with that chart convention. The target is each source leaf's projected area along one fitted normal. Oblique silhouettes, overlap, and shadows still require view comparisons. See the [area-fit results](OAK_BRANCH_CLUSTER_LOD_PLAN.md#area-fitted-leaf-representations).

The first automatic cut uses the Oak Branch review to choose LODs 3, 4, and 6. The limits are editable in screen pixels. The estimates use the branch at rest and the shadow pass shares the camera selection. The selector applies its thresholds directly each frame. Near-threshold flicker, shadow changes, and views closer than the current zoom range can motivate revisiting these choices. See the [automatic cut](OAK_BRANCH_CLUSTER_LOD_PLAN.md#first-automatic-cut).

The shadow calibration keeps the current camera-matched cut as the default. The forced override can target whole branches outside the wind-aware camera frustum, with each selected branch still eligible for the light pass. The benchmark pairs frozen camera cuts and fixed shadow settings to measure receiver coverage and timing. Its texel estimates use the geometry at rest and measure transverse displacement. Wind, light-space depth changes, and which receiver sees the shadow enter the render comparison. See the [shadow calibration](OAK_BRANCH_CLUSTER_LOD_PLAN.md#shadow-lod-calibration).

The Phase I voxel bake treats the selected mesh as opaque, two-sided triangle surfaces. All sizes share the mesh-local zero origin and are baked independently from the source. An axis-aligned surface on a grid plane belongs to the positive-side cell. Coverage is estimated from equally weighted axial and diagonal probes. Their hit fractions are diagnostic data, and the asset stores binary occupancy only. The cutoff sweep supplies candidates for image comparisons in Phase II. See the [voxel bake results](OAK_BRANCH_CLUSTER_LOD_PLAN.md#voxel-bake-phase-i).

Phase II compares unlit foliage visibility using matched CPU rays, with fixed bark occlusion and the foliage at rest. The voxel surface depth is the entry point of the first occupied cell. A nearest-hit depth difference can include seeing a different layer of foliage. Gap counts depend on the camera sample lattice and the clear-pixel and minimum-area thresholds, so use coverage and depth maps alongside them. See the [CPU comparison](OAK_BRANCH_CLUSTER_LOD_PLAN.md#cpu-voxel-comparison-phase-ii).

Phase III uses full indexed box proxies and first-hit depth in the camera pass. All forced comparison views use the rest pose and LOD 6 triangle foliage casters. Brick payloads hold occupancy only. The shaded voxel preview uses the leaf texture's coarsest mip color and simple illumination. The coverage view and CPU parity check isolate geometry. The timing applies to this proxy renderer and the selected Oak Branch bakes. See the [GPU comparison](OAK_BRANCH_CLUSTER_LOD_PLAN.md#gpu-voxel-comparison-phase-iii).
